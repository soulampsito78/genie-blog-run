# 2026-11-26 원문 교정 경로와 재발 방지

## 확인된 원인

Today의 기존 `body_only`는 부모의 교정된 문장을 편집하지 않고 고정된 선정 기사 입력으로 다시 생성한다. 따라서 한 문장 오류를 고치려는 재생성에서 다른 카드의 한국 관세 조건과 이미 고친 해석이 사라질 수 있었다. `run_id`만 같은 것도 본문 동일성을 보장하지 않는다. 자동검수의 구조·어휘 검사에는 시장 세션과 발표 시각, 전언의 인물·회사 범위, 지표별 예상치의 의미 대조가 부족했다. 담당자가 임의로 설정한 중간 횟수 상한을 실제 승인된 작업의 종료 조건으로 취급한 것도 별도 실행 판단 오류다.

## 변경과 검증 범위

- 관리자 상세의 문구 편집은 선택한 텍스트 노드만 바꾸고 불변 원문 버전과 조건부 메타데이터 교체로 저장한다. 모델·이미지를 호출하지 않는다. 수정 전 검수는 이력으로 보존하며 현재 자동검수 승계를 거절한다.
- 기존 관리자 승인과 signed 제출은 원문 수정과 같은 회차 잠금을 공유한다. 발송 중·접수·결과 불명·다른 leaf·HOLD는 보존한다. 검수 메일도 시도와 접수 증거를 구분하여 중복 클릭이나 저장 실패로 반복 전송하지 않는다.
- 기존 생성 프롬프트 두 단계와 최종 고객 본문 검사에 인물 직함·복귀 목적지·자산과 회사 인수·보도 추정 거래금액·저장소 점검과 자동 배포·프로젝트 수주액 범위를 추가했다. 발표 시각/사건 시점 주석은 독립 근거가 실제 공급된 때만 사용한다. 주석이 없는 RSS 입력에서도 관찰 가능한 위험한 인과·범위 주장은 원문 검수로 보낸다. 이것은 범용 사실 검증이나 모든 원문 자동 수집 구현이 아니다.
- 해당 사실 경고는 기존 7항목 signed 독립 검수로 해소할 수 있으며 자동 PASS나 재생성 근거로 쓰지 않는다. 알 수 없는 경고·권리·이미지·보안·첫 검수 안전성·수신권한·서명·중복 조건은 유지한다.
- 정상 생성과 이미지 교정 후 실제 운영자 SMTP 접수 필드를 저장하여 후속 후보를 고객 발송 완료로 오인하는 경로를 수정했다.

테스트는 실제 관리자 로그인·CSRF·미리보기·문구 저장 진입점, 원문 불변성과 비대상 문장 보존, 동일 run의 변경 본문에 대한 이전 signed 검수 거절, 수정/승인 동시성, 저장·SMTP 불확실성, 기존 제품·권한·발송 회귀를 포함한다. 실제 배포 커밋·digest·serving과 검증 결과는 비공개 운영 원장에 별도로 기록한다. 이 문서 자체는 배포 또는 고객 발송 완료 증거가 아니다.

## 다음 회차의 동일 이슈

11월 26일 실제 발송 고정 보관본을 한 번 읽기 전용으로 대조했다. 한국 15% 제안은 있지만 조건부 25% 대안은 없다. 이미 접수된 보관본은 보존하고 이 건으로 재발송하지 않는다. [USTR 한국 공고](https://ustr.gov/sites/default/files/files/Press/Releases/2026/Korea%20FRN.pdf)의 실제 **V절, 18–19쪽**에는 최대 15% 기본 제안과 협의·기존 약속이 불충분하다고 판단할 경우 최대 25% 대안이 구분되어 있다. 둘 다 제안이며 기존 MFN·301조 관세를 반영하고 품목 예외가 있다. 다음 회차에 이 이슈를 다시 다룰 때 이 조건을 함께 확인한다. 25% 조건 회귀는 0.25% 지수 등락이나 CSS 너비를 근거로 통과시키지 않는다.

PCE는 전체와 근원의 실제치·예상치·기간·전년 대비/전월 대비를 각각 결속한다. 한 지표의 예상 상회를 다른 지표의 해석에 쓰지 않는다. 원문·예상치의 실제 수집 증거 없이 수치를 새로 확정하지 않는다.
